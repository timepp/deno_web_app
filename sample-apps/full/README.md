# Full Sample

This directory demonstrates the recommended directory and file structure for a medium-to-large Deno UI application:

- `app.ts`: Application entry point. It parses `--appMode`, then calls `startDenoUI()`.
- `api.ts`: Defines the type-safe API shared by the frontend and backend.
- `api-impl.ts`: Implements the local API.
- `frontend/`: Contains the UI entry point, styles, and static assets.
- `build-release-assets.ts`: Builds embedded frontend assets for publishing.
- `release-assets.ts`: Generated embedded assets. Do not edit this file manually.
- `.vscode/`: Development and launch task configuration.

Run in development mode:

```sh
deno run -A app.ts
```

Launch in a standalone application window:

```sh
deno run -A app.ts --appMode
```

## How to publish

The app can be published to [JSR](https://jsr.io/) and run directly from the registry:

```sh
deno run -A jsr:@account/app-name
```

### Before publishing

Generate the embedded assets before publishing:

```sh
deno run -A build-release-assets.ts
```

Locally, `app.ts` leaves `memoryAssets` empty and Deno UI automatically uses Vite. When the app runs from JSR, it loads `release-assets.ts`; Deno UI detects the non-empty assets and automatically uses the static frontend server. There is no release mode or release flag.

Run the build script before every publication to ensure that `release-assets.ts` matches the latest frontend code.

### Publish

Follow the official [JSR publishing instructions](https://jsr.io/docs/publishing-packages). Make sure the generated `release-assets.ts` is included in the published package.
